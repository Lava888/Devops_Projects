# Contributing to DevOps Projects

Thank you for your interest in contributing! Here's how you can help.

## 🐛 Reporting Issues

When reporting bugs or issues:

- Check existing issues first
- Provide clear, descriptive title
- Include:
  - Environment details (OS, tool versions)
  - Step-by-step reproduction
  - Expected vs actual behavior
  - Error messages and logs
  - Screenshots if applicable

## 🚀 Submitting Changes

### 1. Fork & Clone

```bash
git clone https://github.com/YOUR_USERNAME/Devops_Projects.git
cd Devops_Projects
```

### 2. Create Feature Branch

```bash
git checkout -b feature/your-feature-name
```

### 3. Make Changes

- Follow existing code/configuration style
- Keep commits atomic and focused
- Write clear commit messages
- Update relevant documentation

### 4. Test Thoroughly

- Test locally before submitting
- Document any manual testing steps
- Verify no sensitive data is included

### 5. Push & Create PR

```bash
git push origin feature/your-feature-name
```

Then create a Pull Request with:
- Clear description of changes
- Link to related issues
- Testing performed
- Any breaking changes

## 📋 Code/Configuration Style

### Terraform
- Use consistent formatting: `terraform fmt`
- Include variable descriptions
- Add comments for complex logic
- Use meaningful resource names

### Kubernetes
- Use YAML format consistently
- Include labels and annotations
- Document resource purposes
- Follow naming conventions

### Scripts
- Use bash or Python
- Add shebang and comments
- Include error handling
- Make scripts idempotent

## 📚 Documentation

- Update README for new features
- Add setup/usage instructions
- Include examples
- Document prerequisites
- Add troubleshooting section

## ✅ Checklist Before Submitting

- [ ] Tested locally
- [ ] No hardcoded secrets or credentials
- [ ] Code/configs follow style guidelines
- [ ] Documentation updated
- [ ] Commit messages are clear
- [ ] No unnecessary files included
- [ ] Related issues are linked
- [ ] Breaking changes documented

## 🎯 Types of Contributions

We welcome:
- Bug fixes
- New infrastructure examples
- Improved documentation
- Performance optimizations
- Security enhancements
- Better error handling
- Community feedback

## 📞 Questions?

Open a GitHub discussion or issue if you need clarification.

Thank you for contributing! 🙏
